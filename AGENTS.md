# Architecture rules
- GDPR deletion approval is generated by the database from the authenticated second administrator; clients send only the request ID, and processors must atomically claim an approved request before destructive work to prevent forged consent and duplicate execution.- Appointment requests live in their own table and are decided only via the decide_appointment_request RPC (role-checked, creates the appointment atomically); a trigger blocks direct status changes so clients cannot bypass the decider role.
- Case-item triage (ball_owner, next action) logic lives in src/features/cases/items/ball.ts as pure functions; UI and filters import it so rules stay testable in one place.
